PROJECT OBJECTIVE
=================

Build a robust detector for fully AI-generated versus authentic images that
continues to work after common real-world transformations such as JPEG
compression, blur, resizing, noise, brightness, contrast, saturation, and
cropping.

The system is a hackathon/research prototype. A prediction is not proof of image
provenance and must not be the sole basis for moderation, accusations,
disciplinary action, or other high-impact decisions.


SYSTEM ARCHITECTURE
===================

1. Frozen vision backbone:
   openai/clip-vit-large-patch14

2. Immutable Hugging Face revision:
   32bd64288804d66eefd0ccbe215aa642df71cc41

3. CLIP output:
   A normalized 768-value image embedding.

4. Trained classifier:
   A small MLP head named mlp_consistency. CLIP itself was never fine-tuned.

5. Calibration:
   Probability = sigmoid(logit / temperature).
   The decision threshold is stored separately from the probability.

6. Inference flow:
   Image -> EXIF correction -> RGB conversion -> CLIP preprocessing -> frozen
   CLIP embedding -> trained MLP -> calibrated probability.

The shared inference implementation is model/src/inference.py. The graded CLI
is model/scripts/predict.py. Future API work must use this same InferenceEngine
instead of implementing inference a second time.

CHRONOLOGICAL PROJECT SUMMARY
=============================

STAGE 1 - PROJECT SCAFFOLDING
-----------------------------

The Python model package, configuration, scripts, tests, output structure, and
Git ignore rules were established. The project uses model/configs/default.yaml
as its central configuration. Dataset files, the Hugging Face cache, virtual
environment, raw samples, bytecode, and other large local resources are ignored.


STAGE 2 - CLIP DOWNLOAD AND VERIFICATION
----------------------------------------

The project uses OpenAI CLIP ViT-L/14 from Hugging Face. It is pinned to the
immutable revision listed above and cached under .cache/huggingface/. The model
weights are not copied into Git.

The shared loader freezes every CLIP parameter and loads the model offline after
the first download. Verification checked:

- Pinned immutable revision
- Frozen parameters
- Embedding shape [batch, 768]
- Finite values
- Near-unit L2 norm
- Repeatable inference
- CUDA mixed-precision operation

Commands:

  python -m model.scripts.download_model --config model/configs/default.yaml
  python -m model.scripts.download_model --verify-only --offline

The first command accesses Hugging Face. The second command must succeed with
network fallback disabled.


STAGE 3 - DATASET ACQUISITION
-----------------------------

SID_Set is the core training dataset. Its pinned Hugging Face revision is:

  dc03ead57929879319ce30a82bfcfb8d317b10bd

The full SID_Set is approximately 140 GB, so the project uses deterministic
Tier A sampling rather than downloading/materializing the entire dataset.

Final SID Tier A source counts:

- Training: 5,000 real + 5,000 fully synthetic = 10,000
- Calibration/validation: 1,000 real + 1,000 synthetic = 2,000
- Internal final evaluation: 1,000 real + 1,000 synthetic = 2,000
- Tampered diagnostics: up to 250
- Total retained SID records: 14,250

SID labels:

- 0 = real
- 1 = fully synthetic
- 2 = partially tampered, diagnostic only

SID currently exposes no public official test split. The calibration and
internal final-evaluation roles are disjoint selections derived from upstream
validation data. The latter must not be described as an official SID test.

CIFAKE was downloaded separately. It contains:

- train/REAL: 50,000
- train/FAKE: 50,000
- test/REAL: 10,000
- test/FAKE: 10,000

Only the 20,000-image CIFAKE test split is used, and only for cross-dataset
evaluation. CIFAKE never enters training, checkpoint selection, calibration, or
threshold selection. Its images are 32x32 and are upscaled for CLIP, which is a
major evaluation caveat.

WildFake was explicitly omitted because the exact challenge-supplied subset was
not available. It must not be retroactively presented as used.

The authoritative inventory is:

  resources/datasets/dataset_inventory.json

Raw datasets remain under resources/datasets/ and are ignored by Git.


STAGE 4 - MANIFESTS, LEAKAGE, AND TRANSFORMS
--------------------------------------------

The pipeline builds Parquet manifests rather than expanding all SID images into
ordinary image folders. A manifest records the source identifier, native
location, official split, label, role, dimensions, SHA-256, perceptual hash, and
source group.

Core generated manifest artifacts:

- model/outputs/manifests/dataset_manifest.parquet
- model/outputs/manifests/training_augmentation_plan.parquet
- model/outputs/manifests/evaluation_descriptors.parquet
- model/outputs/manifests/leakage_report.json

Transforms occur before CLIP preprocessing. The graded registry includes JPEG,
blur, downscale/upscale, Gaussian noise, brightness, contrast, saturation, and
center crop conditions. Separate held-out conditions include WebP quality 50,
JPEG quality 50 followed by resize 0.5, and JPEG quality 20.

Each training source receives:

- One clean descriptor
- Two deterministically planned transformed descriptors

This changes 10,000 training sources into 30,000 training embeddings. It does
not create 30,000 independent source images.

Exact cross-split duplicates are treated as fatal. Near duplicates were reported
and reviewed rather than silently moved. The duplicate issue was investigated,
the affected SID evaluation material was repaired/replaced, and manifests were
rebuilt. Official split identity and source grouping were preserved.


STAGE 5 - EMBEDDING EXTRACTION
------------------------------

CLIP embeddings were extracted once and stored in disk-backed safetensors
shards with Parquet sidecars. Transformed image copies were not stored.

Final embedding counts:

- train: 30,000
- val/calibration: 46,000
- test/internal evaluation: 46,000
- tampered diagnostic conditions: 5,750
- CIFAKE clean: 20,000
- total: 147,750
- approximate stored embedding size: 218.47 MiB

Each embedding has 768 float values, is finite, and is approximately unit norm.
Sidecars preserve source_id, split, label, condition, seed, shard, and row
offset. Cache fingerprints prevent incompatible datasets, transforms, model
revisions, or sampling plans from being combined.

The most serious technical problem occurred here. The original SID loader
cached complete Parquet image columns and eventually consumed all 32 GB of
system RAM. The process was stopped. The loader was redesigned to:

- Process one Parquet file sequentially
- Read bounded row groups
- Retain at most one Parquet image column
- Limit decoded-image prefetch to one GPU batch
- Release unused Arrow memory before opening the next file
- Resume only from completed shard boundaries

After the fix, peak system RAM was approximately 4.2 GiB instead of 32 GB.
Batch size 32 and four workers were stable on the RTX 5080.


STAGE 6 - CLASSIFIER TRAINING
-----------------------------

CLIP was not loaded during head training. Only classifier heads were trained on
cached embeddings.

Core seed-42 experiments:

- linear_clean
- linear_robust
- mlp_robust
- mlp_consistency

Extra seeds 43 and 44 were run for mlp_robust and linear_robust. The consistency
model adds a penalty when clean and transformed views of the same source produce
different logits.

Training outputs are under model/outputs/training/. The detailed record is:

  report/training_report.md

The ultimately frozen model is mlp_consistency, seed 42.

Selection and calibration used SID validation clean plus the 19 graded

WildFake, and tampered data were excluded from selection and thresholding.

Frozen model identity:

- Experiment: mlp_consistency
- Seed: 42
- Temperature: 0.32979855563148874
- Threshold: 0.6069634556770325
- Checkpoint SHA-256:
  0090b39eac281125d2de72921dcc0f182b1656ed6fcca232b5385276a6301088

Headline results:

- SID internal evaluation clean balanced accuracy: 0.9925
- SID graded worst-condition balanced accuracy: 0.9855
- SID graded macro balanced accuracy: 0.9907
- SID held-out worst-condition balanced accuracy: 0.9790

STAGE 9 - CLI INFERENCE
-----------------------

The graded command is:

  python model/scripts/predict.py --input_dir <directory> --output <predictions.json>

It recursively discovers static .jpg, .jpeg, .png, and .webp files in
deterministic relative-path order. It corrects EXIF orientation, converts images
to RGB, batches inference, and writes atomic JSON.

Required prediction schema:

  [{"image_path":"nested/example.jpg","pred":0.7312}]

Unreadable files are skipped, warned about on stderr, and recorded separately
in <output-stem>.errors.json. Error objects are never mixed into the prediction
array.

The CLI supports:

- --input_dir
- --output
- --checkpoint
- --config
- --device auto|cpu|cuda
- --batch-size
- --verbose

The shared InferenceEngine loads CLIP and the head once per process. It uses
offline=True for CLIP and verifies the default checkpoint SHA-256.

Stage 9 verification:

- CUDA: 4 readable CIFAKE smoke images, 0 errors
- CPU: 4 readable CIFAKE smoke images, 0 errors
- Repeated CUDA JSON: byte-identical
- Direct InferenceEngine match: maximum difference 0.0
- CPU versus CUDA maximum probability difference observed: approximately
  0.00366 due to float32 CPU versus float16 CUDA computation
- Final test suite after bundle migration: 46 passed

Report:

  report/cli_report.md


FINAL RUNTIME MODEL BUNDLE
==========================

The three production/runtime files are consolidated under:

  model/outputs/final/checkpoint.pt
  model/outputs/final/metadata.json
  model/outputs/final/frozen_model.json

The checkpoint and metadata are copies of the selected training-run artifacts.
The originals remain under model/outputs/training/mlp_consistency/seed_42/ for
training provenance.

frozen_model.json points to model/outputs/final/checkpoint.pt and contains the
temperature, threshold, selected experiment, metrics, and checkpoint SHA-256.
Inference rejects a corrupted or mismatched default checkpoint.

MAJOR DIFFICULTIES AND RESOLUTIONS
==================================

1. SID size and access
   The full dataset is approximately 140 GB. Tier A deterministic streaming was
   chosen to keep storage and hackathon time manageable. Downloads were stopped
   and resumed more than once while source behavior and size were clarified.

2. Confusion about Hugging Face load_dataset
   Calling load_dataset does not necessarily mean all 140 GB must be
   materialized when streaming and explicit quotas are used. The downloader was
   designed around pinned revisions, streaming, deterministic sampling, and
   resumability.

3. CIFAKE versus SID roles
   CIFAKE was considered as a possible fallback training set because it was
   easier to access. The final decision was to train only on SID and use CIFAKE
   strictly as a cross-dataset benchmark because CIFAKE's 32x32 images differ
   substantially from the SID domain.

4. Duplicate and near-duplicate images
   Exact leakage is dangerous because it can inflate evaluation results. Exact
   cross-split duplicates were treated as fatal; near duplicates were surfaced
   for manual review. Affected SID evaluation material was repaired and the
   manifests were regenerated rather than simply ignoring the problem.

5. 32 GB RAM exhaustion
   The first embedding extraction cached too much Parquet image data. It used
   essentially all system RAM and was stopped. Sequential bounded row-group
   loading fixed the issue and reduced peak RAM to approximately 4.2 GiB.

6. Repeated sample-size changes
   Training was discussed at 15,000 versus 30,000 embeddings. The final choice
   returned to 30,000 because extraction time was acceptable after the memory
   fix. This represents 10,000 source images with three views each.

7. Calibration larger than training
   Validation and evaluation have 2,000 source images each but enumerate clean,
   all graded, and held-out conditions, producing 46,000 embeddings per scope.
   This is expected and does not mean they contain more independent sources.

8. CPU versus CUDA results
   Same-device repeated predictions were identical. Small cross-device numeric
   differences are expected because CUDA uses float16 and CPU uses float32.

9. Weak cross-dataset generalization
   CIFAKE balanced accuracy is only 0.5706. This is a real limitation, not a CLI
   failure. It must be disclosed in demos and documentation.

10. Artifact packaging
    Initially, checkpoint.pt and metadata.json lived only inside the training
    experiment directory while frozen_model.json lived under final/. They were
    consolidated into a verified three-file final bundle for easier deployment.

11. SHA-256 concern
    Publishing a SHA-256 is safe. It is not a password or encryption key and
    cannot realistically reconstruct the checkpoint. It protects users from a
    corrupted, modified, or incorrect model file, so verification was retained.

12. Git audit
    The current tree and full commit history were scanned. No credentials,
    tokens, private keys, personal absolute paths, raw datasets, or Hugging Face
    cache files were found. Two tracked Matplotlib font cache files were noted
    as unnecessary repository noise:

      model/outputs/evaluation/final/.mplconfig/fontlist-v390.json
      model/outputs/training/.mplconfig/fontlist-v390.json

    They are not sensitive. A 33 MB validation_predictions.csv is also tracked;
    it is not sensitive and is below GitHub's 100 MB limit, but it contributes
    repository size. Decide during Stage 12 whether machine-readable submission
    evidence justifies keeping it.

MACBOOK SETUP
=============

From macOS Terminal (Bash or the default compatible Zsh shell):

1. Clone and enter the repository:

  git clone https://github.com/owjd03/Image-detector.git
  cd Image-detector

2. Create the Python 3.12 environment:

  python3.12 -m venv .venv
  .venv/bin/python -m pip install --upgrade pip

3. Install the platform-appropriate PyTorch 2.8.0 build, then requirements.
   On macOS, PyPI supplies the native build:

  .venv/bin/python -m pip install torch==2.8.0 torchvision==0.23.0
  .venv/bin/python -m pip install -r requirements.txt

4. Download the pinned CLIP model. This requires network access and roughly
   1.7 GB of local cache space:

  .venv/bin/python -m model.scripts.download_model --config model/configs/default.yaml

5. Verify that CLIP can reload fully offline:

  .venv/bin/python -m model.scripts.download_model --verify-only --offline

6. If the final bundle is not present in the Git clone, download and extract the
   GitHub Release asset as documented in README.md. The resulting paths must be:

  model/outputs/final/checkpoint.pt
  model/outputs/final/metadata.json
  model/outputs/final/frozen_model.json

7. Verify the checkpoint:

  sha256sum model/outputs/final/checkpoint.pt

Expected:

  0090b39eac281125d2de72921dcc0f182b1656ed6fcca232b5385276a6301088

8. Run tests:

  .venv/bin/python -m pytest -q

9. Create an images directory, add one or more images, and run CPU inference:

  mkdir -p images
  .venv/bin/python model/scripts/predict.py \
    --input_dir images \
    --output predictions.json \
    --device cpu

The current device choices are auto, cpu, and cuda. On macOS, auto currently
falls back to CPU; an explicit Apple Silicon MPS path has not been implemented.
